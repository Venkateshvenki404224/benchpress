# Leases and credits

On a server with credits switched on, a deploy buys a fixed window of time and
the bench stops when the window closes. This page reads the clock, renews it,
and explains every line in the ledger.

**Who this is for.** Anybody using a BenchPress server that charges for time.

**Before you start.** Credits are off by default, and off means the feature
does not exist. With credits off there is no countdown, no meter in the
sidebar, and `/frontend/credits` sends you back to Labs. If your server looks
like that, skip this page. Nothing on it applies.

## What costs credits

Two things, and the Credits screen says so at the top.

| Action | Cost |
|---|---|
| The lease an instance runs on | the plan's price |
| A custom image build nobody has built before | 40 credits |
| Creating a site | free |
| Registering a device | free |
| A build that fails | free |

## Buying credits

Press a pack on the Credits page and BenchPress opens an order with the
payment gateway. The price is read from the pack, never from the browser, so
the amount cannot be changed on the way.

![The Credits page after pressing the Regular pack at 1280 by 800 pixels. The Regular card is highlighted and a red message under the three packs reads, Password not found for Razorpay Settings Razorpay Settings key_secret. The Balance tile still reads 55 of 65 allocated, the Entries tile still reads 4, and the ledger below is unchanged with its four rows.](../images/user/leases-and-credits/07-checkout-handoff.png)

The frame above is a server whose gateway has no keys configured. The press
reaches the gateway handoff and stops there with
`Password not found for Razorpay Settings Razorpay Settings key_secret`.
Nothing is charged and the ledger does not change.

With keys configured, the press opens a checkout instead. Credits land in the
account when the payment settles, as a `Purchase` row in the ledger.

**A purchase is applied exactly once.** The gateway retries, and every retry
is matched against the order already settled.

| Pack | Credits | Price | Per credit |
|---|---|---|---|
| Starter | 200 | ₹499 | ₹2.50 |
| Regular | 1,000 | ₹1,999 | ₹2.00 |
| Heavy | 4,000 | ₹6,999 | ₹1.75 |

There are no subscriptions and no auto-renewal. Money buys credits, and
credits buy time.

## Verify

- The Labs row for a running bench shows `Lease ends in …`.
- The countdown falls by one second a second.
- After a renewal the countdown jumps by the plan's duration and the meter
  falls by its price.
- The Credits page shows one `Usage` row for the renewal, with the new
  balance in **Balance after**.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| No countdown and no meter | Credits are switched off on this server | Nothing to do. There are no leases |
| `/frontend/credits` sends you to Labs | Same. The screen exists only while credits are on | Ask the operator whether credits are meant to be on |
| No **Renew** button beside the countdown | The bench never held a lease | Redeploy it |
| `Not enough credits` | The plan costs more than is available | Pick a shorter plan, or buy credits |
| The refusal names less than the balance | Credits are reserved against a running deploy | Stop an instance, or buy credits |
| `A lease on this lab cannot run longer than … minutes` | The plan would push the lease past the lab's ceiling | Pick a shorter plan |
| `This bench is already stopping` | The expiry sweep claimed the row first | Wait for the stop, start the bench, then renew |
| `This bench has been torn down. Redeploy it` | The stopped container was reaped | Redeploy. A new lease starts with it |
| `Credits are switched off on this site` | Credits were turned off between opening the dialog and pressing it | Reload the page |
| A purchase fails at the gateway | The server has no gateway keys | Ask the operator. Nothing was charged |
| The deadline passed and the bench is still up | The sweep that stops expired leases is not running | Tell the operator. The clock is right, the sweep is not |

## Reference

### The lease clock

The deadline is a fixed instant stored on the bench. Nothing accrues and
nothing settles later. A deploy spends the plan's price once and writes the
deadline.

A scheduled sweep on the server claims each due lease and hands the stop to a
background worker. **That sweep, not the browser, is what stops a bench.** A
server whose sweep or stop worker is not running keeps benches alive past
their deadline. The countdown still tells the truth about the deadline.

### After the deadline

A stop keeps the container. It is a stop, not a delete.

| Then | What happens |
|---|---|
| The bench stops | The container is kept. The database is kept |
| Inside the grace window | **Renew** starts the same container again |
| After `reap_after_days` | The container is removed. Only a redeploy brings it back |

`reap_after_days` is 7 on this server. `0` turns the deletion off.

### Ledger entry types

| Type | Sign | Written by |
|---|---|---|
| `Grant` | + | signup, or an operator granting credits |
| `Purchase` | + | a settled payment |
| `Usage` | − | a lease, or a custom image build |
| `Refund` | − | credits taken back |
| `Adjustment` | ± | an operator correcting an account by hand |

An `Adjustment` moves a balance without a payment. It is how an operator tops
up an account on a server with no gateway.

### The meter

| Figure | Meaning |
|---|---|
| Balance | what is left to spend |
| Allocated | the balance plus everything already spent |
| Entries | how many ledger rows the account has |

Allocated holds still while the balance falls, which is what makes the bar
read as a gauge. A refund or a negative adjustment lowers it, because those
credits were taken back.

The meter turns a warning color below 20% of allocated.

### Concurrency

How many instances one account may run at once depends on whether credits are
on, and whether the account has ever bought any.

| Account | Limit here |
|---|---|
| Credits off | unlimited |
| Credits on, never purchased | 2 |
| Credits on, has purchased | 5 |

`0` in any of these settings means unlimited. A refusal names the number that
was hit.

### Renewing is free of the concurrency cap

The cap forbids new instances, not touching existing ones. A renew, a restart
and a retry on a bench you already hold are never refused for concurrency.
They can still be refused for credits.
